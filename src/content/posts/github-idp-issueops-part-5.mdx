## 1. The flaw in what I already shipped

[Part 1](/posts/github-idp-issueops-part-1/) drew the trust cut. [Part 2](/posts/github-idp-issueops-part-2/) made the Issue Form the portal. [Part 3](/posts/github-idp-issueops-part-3/) walked App PR → `tofu-pipeline`. [Part 4](/posts/github-idp-issueops-part-4/) was bootstrap and harden.

That arc is a **day-1 / day-0** story: request → Git → plan → gated apply. It assumes the happy path stays happy. It does not.

**What’s missing:** after apply, the cloud can diverge from Git — console edits, “quick” IAM tweaks, a deleted tag, a renamed bucket. Parts 1–4 never scheduled a plan against live state. We said “Git is source of truth” and then looked away. That’s a design hole, not a footnote.

Worse trap if you “fix” it wrong: a reconcile job that re-applies desired state **including destroys**. Someone ClickOps’d a rename; OpenTofu wants to delete the old name. An unattended stamp merge at 3 a.m. is how you teach the org that GitOps is scary.

So the flaw is twofold:

1. **No detect** — drift is invisible until the next human PR.  
2. **Unsafe solve** — blind reconcile can destroy.

Control still must not grow a second apply path. The fix stays on the **workload**, same trust domain as [part 1](/posts/github-idp-issueops-part-1/).

## 2. What we actually need

| Need | Why |
| --- | --- |
| Workload-owned cron / dispatch | Detect means `tofu plan` + OIDC — control never holds that |
| One Drift Report issue | Rolling signal operators can triage |
| Split **safe** vs **destroy** | create/update ≠ delete/replace |
| Dev: stamp PR for safe only | Reuse `tofu-pipeline` + Environment gate — no apply-on-`main` side door |
| Prod: report only | Humans open PRs; no quiet reconcile |
| Conftest deny destroy on `drift/*` | Belt and suspenders if a stamp PR ever carries a delete |

That’s the product. Not a portal. Not a second control plane.

## 3. What I’m doing about it

Greenfield in `gh-platform-actions` (not bolted onto an old auditor from another monorepo):

| Piece | Role |
| --- | --- |
| `drift-reconcile.yml` | Reusable workflow — OIDC plan, issue, optional stamp PR |
| `scripts/drift_reconcile.py` | Parallel plans, classify, GitHub issue/PR |
| `policies/conftest/terraform-drift/` | Deny `delete` on `drift/*` heads inside `tofu-pipeline` |
| `examples/infra-*/drift.yml` | Dev: `open_reconcile_pr: true` · Prod: `false` |

Flow:

```text
schedule / workflow_dispatch on infra-<env>
        │
        ▼
drift-reconcile@pinned-SHA     plan every stacks/* root
        │
        ├── clean     → close Drift Report / stale stamp PR
        ├── safe      → report (+ stamp PR on dev)
        └── destroy   → report only (never stamp PR)
        │
        ▼
tofu-pipeline on stamp PR      plan → (merge) → Environment apply
                               + Conftest deny destroy on drift/* branches
```

Assumes you already stood up parts 1–4: pinned `tofu-pipeline`, private workloads, OIDC that can plan on `main` for schedule (detect has **no** Environment gate — same idea as the pipeline `plan` job).

## 4. Classify before you reconcile

Every stack plan lands in one bucket:

| Class | Plan shape | Auto stamp PR? |
| --- | --- | --- |
| **clean** | No changes | — |
| **safe** | `create` / `update` only | Dev: yes · Prod: no |
| **destroy** | Any `delete` (including replace) | **Never** |

That split is the whole fix. Re-applying Git when someone ClickOps’d a tag is boring and correct. Re-applying when the plan wants to **destroy** a bucket because someone renamed it in the console is how you get a memorable afternoon.

**Env policy:**

| Repo | Drift Report issue | Stamp PR |
| --- | --- | --- |
| `infra-dev` | Yes | Yes (safe only) |
| `infra-prod` | Yes | No — humans open PRs |

## 5. Wire drift-reconcile

Copy the example callers (same Actions SHA as `tofu.yml` / `pins.yaml` **after** the workflow is on the SHA you pin):

- [`examples/infra-dev/.../drift.yml`](https://github.com/ravichandrapatel/gh-platform-control/blob/main/examples/infra-dev/.github/workflows/drift.yml) — `open_reconcile_pr: true`
- [`examples/infra-prod/.../drift.yml`](https://github.com/ravichandrapatel/gh-platform-control/blob/main/examples/infra-prod/.github/workflows/drift.yml) — `open_reconcile_pr: false`

```yaml
name: drift
on:
  schedule:
    - cron: "0 6 * * 1-5"
  workflow_dispatch:

jobs:
  drift:
    uses: OWNER/gh-platform-actions/.github/workflows/drift-reconcile.yml@<40-char-sha>
    with:
      aws_role_arn: arn:aws:iam::ACCOUNT:role/gh-platform-dev
      open_reconcile_pr: true   # false on prod
    secrets:
      modules_git_token: ${{ secrets.MODULES_GIT_TOKEN }}
```

**OIDC note:** IAM trust must allow the schedule/dispatch subject on `main` (often `ref:refs/heads/main`), not only `environment:dev` / `environment:prod`.

Docs: [drift-reconcile](https://github.com/ravichandrapatel/gh-platform-actions/blob/main/docs/workflows/drift-reconcile.md).

## 6. How to solve it

### Safe drift on dev

1. Cron opens/updates **Infrastructure Drift Report**.  
2. For create/update-only stacks it opens/updates `drift/reconcile` with a tiny `stacks/<name>/.drift-reconcile` stamp (so `tofu.yml` path filters fire).  
3. Review the PR — plan should restore Git desired state.  
4. Merge → Environment-gated apply (same gate as IssueOps).

Git was already right; the stamp is a ticket into the existing pipeline.

### Prod (report only)

Read the issue. Open a normal workload PR (or encode an intentional cloud change into Git). Same reviewers, same Conftest, same Environment approval.

### Expected / noisy drift

Pass `exclude` patterns (substring or `stack:substring`). Matching addresses are **dropped from the drift count** (a stack can become `clean`). Keep that list short.

## 7. Destroy is a different product

If the plan includes **any** delete:

1. **No stamp PR.**  
2. The Drift Report lists stack + address + actions.  
3. A human decides: fix ClickOps to match Git, or change Git to match reality.  
4. `tofu-pipeline` still runs Conftest `terraform-drift` on `drift/*` PRs and **fails** if a delete appears anyway.

Intentional teardown stays a normal Git PR on a non-`drift/` branch — with Environment approval. Drift automation does not get a destroy fast path. On purpose. That’s the correction to the series, not a side note.

## 8. Checklist

| # | Check |
| --- | --- |
| 1 | `drift-reconcile` on a pinable SHA; workloads match `tofu-pipeline` |
| 2 | `drift.yml` on `infra-dev` with `open_reconcile_pr: true` |
| 3 | `drift.yml` on `infra-prod` with `open_reconcile_pr: false` |
| 4 | OIDC trust allows schedule on `main` for plan role |
| 5 | Manual `workflow_dispatch` → Drift Report (or closes clean) |
| 6 | Safe tag drift on dev → stamp PR → plan green → apply restores |
| 7 | Destroy plan → **issue only**; `drift/*` + delete fails Conftest |
