## 0. Assumes

Prior posts: [architecture](/posts/github-idp-issueops-part-1/), [operator UX](/posts/github-idp-issueops-part-2/), [provision path](/posts/github-idp-issueops-part-3/), [bootstrap & harden](/posts/github-idp-issueops-part-4/).

You already have `infra-dev` / `infra-prod` calling pinned `tofu-pipeline`. Git is source of truth. Control never holds cloud apply. Good — keep that sentence intact for day-2.

## 1. Why drift is a workload problem

Drift is “cloud reality ≠ Git desired state.” Detecting it means `tofu plan` against real state — which means **OIDC on the workload**, same trust domain as plan/apply.

Control can open Issues and App PRs for *intake*. It must not grow a second apply path “just for drift.” If that sentence feels inconvenient, re-read [part 1](/posts/github-idp-issueops-part-1/).

```text
schedule / workflow_dispatch on infra-<env>
        │
        ▼
drift-reconcile@pinned-SHA     plan every stacks/* root
        │
        ├── clean     → close Drift Report / stale stamp PR
        ├── safe      → report (+ stamp PR on dev)
        └── destroy   → report only (never stamp PR)
        │
        ▼
tofu-pipeline on stamp PR      plan → (merge) → Environment apply
                               + Conftest deny destroy on drift/* branches
```

Reusable pieces live in `gh-platform-actions`:

| Piece | Role |
| --- | --- |
| `drift-reconcile.yml` | Reusable workflow (OIDC plan, issue, optional PR) |
| `scripts/drift_reconcile.py` | Parallel plans, classify, GitHub issue/PR |
| `policies/conftest/terraform-drift/` | Deny `delete` on `drift/*` PRs |

## 2. Classify before you reconcile

Every stack plan lands in one bucket:

| Class | Plan shape | Auto stamp PR? |
| --- | --- | --- |
| **clean** | No changes | — |
| **safe** | `create` / `update` only | Dev: yes · Prod: no |
| **destroy** | Any `delete` (including replace) | **Never** |

That split is the whole product. Re-applying Git when someone ClickOps’d a tag is boring and correct. Re-applying Git when the plan wants to **destroy** a bucket because someone renamed it in the console is how you get a memorable afternoon.

**Env policy (H2):**

| Repo | Drift Report issue | Stamp PR |
| --- | --- | --- |
| `infra-dev` | Yes | Yes (safe only) |
| `infra-prod` | Yes | No — humans open PRs |

## 3. Wire drift-reconcile

Copy the example callers (same Actions SHA as `tofu.yml` / `pins.yaml` **after** you publish the workflow):

- [`examples/infra-dev/.../drift.yml`](https://github.com/ravichandrapatel/gh-platform-control/blob/main/examples/infra-dev/.github/workflows/drift.yml) — `open_reconcile_pr: true`
- [`examples/infra-prod/.../drift.yml`](https://github.com/ravichandrapatel/gh-platform-control/blob/main/examples/infra-prod/.github/workflows/drift.yml) — `open_reconcile_pr: false`

Minimal shape:

```yaml
name: drift
on:
  schedule:
    - cron: "0 6 * * 1-5"
  workflow_dispatch:

jobs:
  drift:
    uses: OWNER/gh-platform-actions/.github/workflows/drift-reconcile.yml@<40-char-sha>
    with:
      aws_role_arn: arn:aws:iam::ACCOUNT:role/gh-platform-dev
      open_reconcile_pr: true   # false on prod
    secrets:
      modules_git_token: ${{ secrets.MODULES_GIT_TOKEN }}
```

**OIDC note:** detect has **no** GitHub Environment gate (same idea as the pipeline `plan` job). Your IAM trust must allow the schedule/dispatch subject on `main` (often `ref:refs/heads/main`), not only `environment:dev` / `environment:prod`.

Docs: [drift-reconcile](https://github.com/ravichandrapatel/gh-platform-actions/blob/main/docs/workflows/drift-reconcile.md).

## 4. How to solve it

### Safe drift on dev

1. Cron opens/updates **Infrastructure Drift Report**.
2. For create/update-only stacks it opens/updates branch `drift/reconcile` with a tiny `stacks/<name>/.drift-reconcile` stamp (so `tofu.yml` path filters fire).
3. Review the PR — plan should restore Git desired state.
4. Merge → Environment-gated apply (same gate as IssueOps).

Git was already right; the stamp is just a ticket into the existing pipeline. No “apply `main` without a PR” side door.

### Prod (report only)

Read the issue. Open a normal workload PR (or encode an intentional cloud change into Git). Same reviewers, same Conftest, same Environment approval.

### Expected / noisy drift

Pass `exclude` patterns into `drift-reconcile` (substring or `stack:substring`) for known benign diffs. Matching addresses are **dropped from the drift count** (a stack can become `clean`). Keep that list short — a long exclude file is how you train yourself to ignore real ClickOps.

## 5. Destroy is a different product

If the plan includes **any** delete:

1. **No stamp PR.** The classifier stops there.
2. The Drift Report lists stack + address + actions.
3. A human decides: fix ClickOps to match Git, or change Git to match reality (import / rewrite / intentional destroy PR).
4. Defense in depth: `tofu-pipeline` runs Conftest `terraform-drift` on any PR whose head ref starts with `drift/` and **fails** if a delete appears anyway.

Intentional teardown of a stack is still a normal Git PR on a non-`drift/` branch — IssueOps or hand-written — with Environment approval. Drift automation does not get a destroy fast path. On purpose.

## 6. Checklist

| # | Check |
| --- | --- |
| 1 | `drift-reconcile` published; workloads pin the **same** SHA as `tofu-pipeline` |
| 2 | `drift.yml` on `infra-dev` with `open_reconcile_pr: true` |
| 3 | `drift.yml` on `infra-prod` with `open_reconcile_pr: false` |
| 4 | OIDC trust allows schedule on `main` for plan role |
| 5 | Manual `workflow_dispatch` produces a Drift Report (or closes clean) |
| 6 | Inject a safe tag drift on dev → stamp PR → plan green → apply restores |
| 7 | Inject / simulate a destroy plan → **issue only**, no stamp PR; `drift/*` PR with delete fails Conftest |
